# Foundation plan

**Goal:** Turn the inherited proxy into `duolane`: an independent, hardened, current Rust product with Claude and Codex backends, built and documented in the owner's style.

**Architecture:** Each slice is one pull request, or a short series, that leaves the default branch green. Remove and rename first so later work touches less code. Harvest comments before other slices rewrite the code they explain.

**Tech stack:** Rust stable, axum, tokio, reqwest with rustls, ratatui, GitHub Actions, cargo-deny, gitleaks, Prettier, markdownlint.

**Spec:** [Architecture](../design/architecture.md), [security](../design/security.md), and the [ADRs](../adr/README.md).

## Global constraints

- Follow `AGENTS.md`, `instructions/`, and the engineering standard.
- Every slice: failing test first where behavior changes, full gates, independent review for code, green CI, merge commit.
- Every slice leaves the README and documents accurate and in the repository's style.
- Tests never touch the home directory or a live backend.
- Keep each slice to one purpose. Do not mix mechanical changes with behavior changes.
- Tags, releases, and crates.io publishing wait for the owner.

## Review focus

- Claude Code's real requests keep working after inbound checks. Record their header names as a fixture first. `HEAD /api/hello` may be rejected, because Claude Code treats it as optional.
- A conversation that moves Claude to Codex to Claude keeps its reasoning, and Anthropic receives no duolane signature or encrypted content.
- A body with no block to convert stays byte-identical on the Claude route, and a converted body changes only the converted blocks.
- A rejected refresh does not delete the Codex login, and a token rotated by the Codex CLI is picked up.
- `--help`, `duolane serve`, `duolane monitor`, and `duolane codex auth status` keep working through renames, comment removal, and file splits.

- [x] **Overflow code on buffered WebSocket.** On the non-streaming WebSocket path, `codex_status_error` keeps only the error text, so a Codex context overflow reported by its `context_length_exceeded` code alone reaches Claude Code as `api_error` instead of `prompt is too long`. Accept: that path keeps the code, and a test covers a code-only overflow there.
- [x] **Remaining live checks.** The [live results](../design/architecture.md#live-results) left a token refresh, the `originator` and `User-Agent` values, a context window overflow, and a switch while a tool call is pending. Accept: each is checked and recorded, or moved to a design's unverified list with a reason.
- [ ] **Buffered overflow.** A non-streaming request over the context window gets HTTP 500 from Responses Lite, three retries, and a 503 instead of `prompt is too long`. Accept: record the upstream error code for buffered 5xx responses, and map a context overflow to the same 400 the streaming path returns without retrying.
- [ ] **Chat Completions source order.** `POST /v1/chat/completions` follows the [source order](../design/openai-api-key.md#order) only when the order is `api-key` alone. With both sources in the order it still uses `chatgpt` only, so it never moves on. Accept: the ChatGPT attempt reports typed failures to the source selector, both orders move on and refuse to move on as the [design](../design/openai-api-key.md#moving-to-the-next-source) says, and hermetic tests cover each.
- [ ] **API key checks outside CI.** Accept: the stored order replacement test passes on native Windows, and the [live checks](../design/openai-api-key.md#testing) run with the owner's approval and are recorded.
- [ ] **Codex socket reuse live check.** The [transport](../design/codex.md#transport-and-retries) reuses a conversation's WebSocket with continuation off. Hermetic tests cannot show that the ChatGPT backend accepts a full-context request on a reused socket. Accept: with the owner's approval, the second request of a conversation is sent on a pooled socket and receives its own answer, a session with parallel agents runs without new error kinds, and the wait before the first upstream event is recorded here against the queue-bound 17 seconds measured on 2026-11-25.
- [ ] **Base instructions live check.** The Codex route sends the catalog's [base instructions](../design/codex.md#base-instructions) before Claude Code's system prompt. On 2026-11-25 Terra agents started by Claude Code ended six delegated tasks early with only that system prompt, while the same model finished the briefs under the Codex client; six runs do not show the cause. Accept: with the owner's approval, a Terra agent given a brief that it ended early on 2026-11-25 is run with the setting on and off, the number of tool calls before its final message and whether the gate ran are recorded here for both, and any misuse of Claude Code's tools is noted.
- [ ] **Stream without final usage.** On 2026-11-25 one of about 420 agent responses on the Codex route ended without final usage, and Claude Code treated it as cut off and asked for the answer again; a second one lacked usage without that effect. Accept: the cause is found in a traffic capture or a hermetic reproduction, the stream always ends with usage or an error, and a test covers it.
- [ ] **Configuration file that fails to parse.** `config.json` is read as one typed document, so one value of the wrong type, such as a string where a boolean belongs, makes duolane ignore the whole file without a message. A configured `authToken` then stops being required. Accept: the [security design](../design/security.md) says what a setting of the wrong type and a file that is not JSON do, a file that sets `authToken` never leads to a proxy that runs without it, the owner sees which setting was rejected, and tests cover a wrong type beside a valid token.
- [ ] **Monitor overview and request phases.** The [monitor design](../design/monitor.md) defines the lane summary, the request phases with their timeline, Wait and First in Recent requests, and the Connections counters; the code has the views, clickable tabs, and the Usage view only. Accept: the Overview matches the design at every layout tier, the snapshot carries the queue place, first upstream event, first output, and connection counters as optional fields without a protocol version change, an attached monitor renders a snapshot without them, and tests cover each rule.
- [ ] **Non-Unix build in CI.** CI runs on Ubuntu only, and a Windows build cannot run on the owner's machine, so a test that names a Unix-only item is caught only by reading. Accept: CI compiles the crate and its tests for a Windows target.
- [ ] **Release archive verification.** The `release` job trusts the aggregate result of the matrix `build` job, which a re-run of one leg can report as success while another leg failed, and its download patterns can match a partial set. Accept: before publishing, the job verifies that all four archives and their checksums are present and each checksum matches, and a test of the workflow structure covers it.
- [ ] **Continuation by default live check.** [Continuation](../design/continuation.md) is on by default from the version after 0.9.0 (owner, 2026-11-25). Accept before that version is tagged, with hermetic tests: a response whose stored and echoed lists are equal is recorded and the next request sends its id with exactly the new items; a rewritten tool argument, streamed text that differs from the final text, a hosted tool call, a reasoning item with different encrypted content, a custom tool call, a function call in a namespace, a message with a citation, an unknown item kind, and a final event without an output list each record nothing; a request whose earlier image or instruction changed sends full context; a compaction request and server compaction each send full context at send time although a response was recorded; and `DUOLANE_CODEX_PREVIOUS_RESPONSE_ID=off` sends full context on every request. Accept after it: with the owner's approval, a day of normal use is measured: the share of Codex requests that sent `previous_response_id`, the fixed delay per request against the 1.4 to 2.0 seconds measured on 0.9.0, any new error kind, and any report that a model lost or contradicted earlier context; the result is recorded in the design's unverified list.
- [ ] **Continuation follow-ups.** A response is recorded once its terminal event is read, even if the client disconnects before reading the last chunk; the next request then sends full context, so this costs speed, not correctness. The buffered variant of the missing-origin test was dropped when buffered responses stopped being recorded. With server compaction on, a native compaction that sees an account change removes every socket of the conversation, including one a newer turn just pooled, which costs one handshake. Accept: recording waits until the body emitted its last chunk, the buffered variant is restored with the expectation that it records nothing, and native compaction removes only its own turn's socket.
- [ ] **Server compaction replay keeps added text.** With server compaction on, a native replay replaces the whole message that holds the summary after finding it as a substring, so text or images the client added to that message are lost. Accept: the replay keeps what the client added or is skipped when the whole message cannot be verified, with a test.
- [ ] **Token counting matches the sent request.** [Token counting](../design/codex.md#token-counting) translates a request differently from the send path in two cases: with an OpenAI API key first in the order it can count the ChatGPT Lite translation although the key sends on the full lane, and for standalone search it counts the system prompt and history that the search payload leaves out. Accept: counting uses the first source's model resolution and translation, standalone search counts `build_search_request`, and a test per case compares the count with the payload that is sent.
- [ ] **Upstream sockets in the descriptor budget.** The intercept [listener](../design/intercept.md#listener) sizes its pools from the open-file limit but does not count the sockets that the relay and the Codex transports open, including background dials and idle pooled connections, so a slow upstream can still exhaust descriptors. Accept: the design states a bound on upstream sockets for the whole life of a socket, the code enforces it, and a test fills it with a slow upstream while the main server still accepts a connection.
- [ ] **Total request body memory.** Each Messages request may hold 64 MiB while it is read, so 512 intercepted connections may hold 32 GiB. Accept: the [limits](../design/security.md#limits) set a bound on the request body bytes held at once and a deadline for reading a body, and tests show that the bound refuses a request, and that a body stalled past the deadline is dropped, returns its bytes to the bound, and lets the next request through.
- [ ] **Optional proxy password.** The intercept listener requires a proxy password, which programs that Claude Code starts inherit in `HTTPS_PROXY`. The owner decided on 2026-11-23 that the listener asks for no password by default, with an option to turn one on. Accept: the [intercept design](../design/intercept.md) defines the option and the move from an install that has a password, the default listener accepts `CONNECT` without credentials and still serves sessions that send the old ones, and tests cover both settings. A review of the draft requires three more things when no password is set: the two Messages paths on the intercepted host refuse any `Origin` and require `application/json` before they read a body, because a browser that uses the proxy and trusts the CA sends `CONNECT` itself; the design claims only that a process holding the port cannot decrypt authenticated TLS; and the old proxy URL in a settings file is recognized by the manifest or other proof before the password file is deleted, or left in place and reported. [Security design](../design/security.md) then limits the inbound token to the main server.
